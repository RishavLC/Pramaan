# TrustBridge

A verifiable-credential layer on Solana. One agency issues a credential, another verifies it,
and the verifier never has to contact the issuer.

**Why:** In Nepal, an address verified by one agency can't be verified by another without manual
steps. TrustBridge anchors only a credential **hash** on-chain, so verification doesn't depend on
any single agency's uptime. No personal data goes on-chain. All sample data is mock.

## How it works

- **On-chain account `CredentialRecord`** (a PDA, never a keypair): `issuer`, `credential_hash`
  (SHA-256), `is_valid`, plus `issued_at`, `revoked_at`, `bump`.
- **PDA seeds:** `["credential", issuer_pubkey, credential_hash]`. A verifier who knows the issuer
  and the credential text can re-derive the address without asking anyone.
- **Instructions:** `issue_credential(hash)`, `verify_credential()` (returns `is_valid`, issuer,
  hash), `revoke_credential()` (original issuer only).
- **Frontend** hashes text in the browser, signs with Phantom, and reads records straight from the
  chain. No backend, no database, no login.

## Prerequisites

Rust, Solana CLI, Anchor 0.31.1, Node 18+, Phantom wallet set to **Devnet**, and a free Helius API key
(https://dashboard.helius.dev).

## Setup

```bash
yarn install                       # root: anchor tests + scripts
cp .env.example .env               # set HELIUS_API_KEY and ANCHOR_WALLET
anchor build
anchor test                        # runs the test suite on a local validator
```

## Deploy to devnet

```bash
npm run deploy:devnet              # = ./scripts/deploy-devnet.sh (preflight-checked)
./scripts/diagnose-deploy.sh       # if deploy fails: read-only report, no secrets
npm run smoke:devnet               # optional end-to-end check on devnet
```

The deploy script prints the program ID and a Solscan link.

## Run the frontend

```bash
npm --prefix app run sync-idl      # copy the real IDL generated by anchor build
cp app/.env.example app/.env.local # set VITE_HELIUS_API_KEY
npm run app:install
npm run app:dev                    # http://localhost:5173
```

> If you redeploy with a new program ID, run `sync-idl` again.

## Tabs

- **Overview**: connection status, program-deployed check, balance, demo steps, hash/PDA preview.
- **Agency A · Issuer**: issue a credential (shows signature + Solscan link) and revoke it.
- **Agency B · Verifier**: verify by PDA, or by credential text + issuer. Shows issuer, valid or
  revoked, and hash, with an optional trusted-issuer whitelist. Works with no wallet connected.
- **History**: latest program transactions via Helius RPC, labelled, with Solscan links.

## 60-second demo script

1. Open the app. Connect Phantom on devnet.
2. Go to **Agency A · Issuer**. Enter `Rishav Shrestha, Kathmandu-10, verified 2026-10-02`. Click **Issue Credential**.
3. Show the transaction signature and click the Solscan link.
4. Click **Verify as Agency B →**. The credential PDA is already filled in. Click **Verify Credential**.
5. Show the result: "Valid. Issued by [Agency A pubkey]."
6. Go back to **Agency A · Issuer**. Click **Revoke Credential**.
7. Click **Verify again →**, then **Verify Credential**. Show: "Invalid. Credential revoked."
8. Say: "This verification worked without Agency B ever contacting Agency A."

(Optional: open **History** to show all three transactions with Solscan links.)

## Security notes

- Only hashes are stored on-chain. Anyone who can guess a credential's full text could confirm it
  matches; production use should add a per-credential salt held off-chain.
- Revocation is enforced by the program (`has_one = issuer` plus a signer check).
- The verifier decides which issuers to trust (whitelist); the program does not.
